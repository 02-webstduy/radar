# 每日技术雷达：分析、取舍与两周计划

> 2026-10-31。先回答四个问题：有人做过吗、面试值不值、商业值不值、难在哪；最后给一个能两周跑起来的计划。

## 0. 一句话

**不是一个"资讯聚合器"，而是一个把「今天读什么 → 这周做什么 → 下一步往哪走」串起来的个人雷达。**
单点功能都有人做，闭环没人做——这就是你的位置。

## 1. 把想法拆成四个能力

1. **按角色采集**：工程师（新技术/文档/开源）或科研（论文/方向）
2. **个性化筛选**：不是按关键词堆 50 条，而是 5 条"与你有关"的
3. **理解进度**：你在做什么、卡在哪、这周推进了多少
4. **给方向**：基于上面三件事，给出可验证的下一步，并且允许人微调

## 2. 已经有人做到哪一步（截至 2026-10-31）

| 类型 | 代表 | 已经做到的 | 没做到的 |
|---|---|---|---|
| 开发者资讯 | [daily.dev](https://docs.daily.dev/intro)（GitHub 20.1k） | 2000+ 源、个性化 feed、社区、AI 标题清洗、职业模式 | 不接你的项目进度，不给方向 |
| RSS + AI | Feedly（Leo）、Inoreader、[Readwise Reader](https://readwise.io/read) | 订阅、AI 排序/摘要、稍后读 | 摘要与"你正在做的事"无关 |
| 论文日报 | [Zotero-arXiv-Daily](https://github.com/TideDra/zotero-arxiv-daily)（6.1k）、[arxiv-sanity](https://github.com/karpathy/arxiv-sanity-lite)、HF Daily Papers | 按兴趣推论文、邮件、零成本 GitHub Actions | 不读你的进度，不给研究方向的判断 |
| 论文助手 | [Elicit](https://elicit.com)、[Undermind](https://undermind.ai)、Consensus、[PaperQA2](https://github.com/Future-House/paper-qa)（9.5k） | 检索、综述、问答、引用 | 是"查资料"的工具，不是"每天推给你"的雷达 |
| 个人知识库 | [Khoj](https://github.com/khoj-ai/khoj)（37.9k）、[Open Notebook](https://github.com/lfnovo/open-notebook)（41k）、AnythingLLM | 文档问答、资料整理、定时研究/简报 | 不知道你在推进什么，更不会给方向 |
| 技术雷达 | [Thoughtworks Technology Radar](https://www.thoughtworks.com/radar)、各种 build-your-own-radar | 方向判断、成熟度分级、团队共识 | 编辑部的、季度的、不个性化、不连续 |
| 职业规划 | 各类 AI career coach、[GradGear 论文](https://ieeexplore.ieee.org/document/11590125) | 简历、面试、技能差距 | 不懂技术内容，给的是"通用职业建议" |

**结论**：四个能力各自都有成熟玩家，**没有产品把"读到的内容"和"你正在做的事"连起来**。你看到的"大家都做完了"，是每个点都有人做；没人做的是**闭环**。

## 3. 差异化：只打三个楔子

| 楔子 | 具体做法 | 为什么别人不做 |
|---|---|---|
| **A. 进度闭环（核心）** | 每条内容都标注"和你当前项目/卡点的关系"；每周三问（做了什么/卡在哪/下周想验证什么）→ 3 个方向卡，每张带证据和"7 天能做的验证" | 需要同时拿到内容和你的私有进度，通用产品拿不到 |
| **B. 证据链** | 每句摘要带原文引用/链接；没有来源的判断标"推测"；不编数字 | 大多数摘要器不强制引用，成本更高 |
| **C. 角色自适应** | 工程师/科研两种模式：源、排序、模板、术语都不同；可对比 | 通用阅读器只换标签，不换管线 |

中文生态（机器之心、掘金、少数派、TLDR、GitHub、HN + arXiv）是内容壁垒，不是技术壁垒——但对中文用户就是差别。

## 4. 面试价值：值，但别做成"RSS + 调 API"

**能讲的技术点**（对应 AI 应用岗 JD）：

| 能力 | 你会在项目里做什么 | 面试可讲 |
|---|---|---|
| 数据采集/清洗 | 多源适配器、限流、增量、去重 | 源不稳定时怎么降级 |
| 排序 | 关键词 + 质量信号 + 反馈加权、多样性重排 | 冷启动怎么办、怎么防茧房 |
| LLM 管线 | 摘要 + 引用对齐 + "为什么与你有关" | 怎么防幻觉、怎么控成本 |
| 评测 | 30 条人工标注、nDCG、引用覆盖率、7 日打开率 | 你怎么证明它变好了 |
| 后端/前端 | FastAPI + SQLite + 简单页面 + 推送 | 为什么先做邮件不做网站 |
| 运维 | 定时、重试、告警、缓存 | 失败隔离 |

**能讲的故事**：不是"我做了个聚合器"，而是"我做了个闭环雷达，用 30 条标注把 top-5 相关性从 A 提到 B，引用覆盖率 100%，7 天里有 5 天真的打开了"。

**风险**：如果只做"抓取 + 摘要 + 列表"，面试官会把它归为 CRUD + API 调用。必须有一个可量化的改进和一个真实的失败分析。

## 5. 商业价值：先别当生意

| 方向 | 付费意愿 | 难点 | 判断 |
|---|---|---|---|
| 个人订阅 | 低（Feedly/Readwise/daily.dev 已占位，AI 日报免费的一堆） | 获客成本远高于订阅费 | 不建议作为生意 |
| 团队技术雷达 | 中高（Tech Lead/架构组） | 要销售、要团队协作、Thoughtworks 有品牌 | 有机会，但不是一个人先做的 |
| 实验室/科研组文献监测 | 中 | Elicit/Undermind/数据库厂商在打 | 可做垂直 |
| 中文 AI 工程师/求职者 | 低到中 | 小众但精准 | 适合先验证 |

**诚实的结论**：作为作品集，价值高；作为生意，先验证再谈。验证方式：先给自己用两周，再找 5–10 个同类人试用，看他们第 7 天还在不在用——比先做网站有意义。

## 6. 技术难点（按风险排序）

| 难点 | 为什么难 | 对策 |
|---|---|---|
| 源与合规 | 反爬、ToS、限流；微信/知乎基本不可碰 | 只走官方 API/RSS；arXiv、GitHub、HN、HF 镜像、机器之心、掘金、少数派、TLDR 都实测可用 |
| 去重与聚类 | 同一新闻多源转载、论文多版本 | URL 规范化 + 标题指纹；跨源按实体聚类；先规则后 embedding |
| 冷启动画像 | 新用户没有行为数据 | 引导填 5 项（方向/技术栈/当前项目/每周可投入时间/讨厌什么） |
| 排序与反馈 | 小样本、位置偏差 | 先加权打分（新近/来源/关键词/质量），再做 save/skip 的简单学习 |
| 摘要忠实性 | 长文 + 幻觉 + "与你有关"需要上下文 | 只允许基于原文的抽取式要点；引用必须带 span；无法判断就写"不确定" |
| 进度理解 | 你的工作数据脏、私有、不结构化 | 先每周手填三问（30 秒），再接 GitHub/笔记；不要一上来做自动挖掘 |
| 方向生成 | 最容易变成"正确的废话" | 方向卡必须含：证据（3 条内容）、假设、7 天验证、止损条件；没证据就不给 |
| 评测 | 相关性标签少、忠实性难自动判 | 30 条人工标注 + 引用覆盖率 + 每周你自己打分；LLM 只做初筛 |
| 成本/运维 | 每条都调 LLM 会贵、会挂 | 批量 + 缓存 + 只对 top-10 做摘要；失败只影响当天 |

## 7. 架构（P0 足够简单）

```text
sources ──► normalize ──► dedupe/cluster ──► enrich ──► rank ──► summarize(cite) ──► deliver
 arXiv       统一 item      URL/标题指纹      元数据      profile     每句带来源       网页/邮件
 HF mirror    schema        跨源聚类          质量信号    反馈权重     "与你有关"       存档
 GitHub API
 HN / RSS
      ▲                                                        │
      └──────────── feedback（保存/跳过/读完） ◄────────────────┘
                              │
                    每周三问 ──► 方向卡（3 个，含证据与 7 天验证）
```

技术栈：Python 3.12 + FastAPI + SQLite；httpx + feedparser；OpenAI 兼容 API（DeepSeek 等）；前端先用一个只读页面，P2 再做交互。

## 8. 两周计划（先证明内容有用，再做网站）

### P0：能每天看（第 1 周）

- 源：arXiv（cs.AI/cs.CL/cs.SE）+ Hugging Face 镜像 + GitHub（搜索/趋势）+ HN + 机器之心（5 个够）
- 画像：引导填 5 项，存 SQLite
- 管线：归一 → 去重 → 打分 → 只对 top-8 做摘要（每条 3 行：是什么 / 为什么与你有关 / 原文链接）
- 交付：本地网页（只读）+ 每天早上邮件/飞书
- 评测：30 条人工标注，算 nDCG@10 和引用覆盖率

**验收**：连续 7 天每天 5 条；0 重复；每条有链接和来源；你自己 7 天里至少打开 5 天；nDCG 有基线数字。

### P1：能闭环（第 2 周）

- 反馈：保存/跳过/读完了；排序加权
- 每周三问 → 3 张方向卡（证据 + 7 天验证 + 止损）
- 记录"这周真的做了哪张卡" → 行动率

**验收**：你自己盲选 20 对（新旧排序），新排序胜率 ≥60%；一周至少落地 1 个 7 天实验。

### P2：网站与整合（第 3–4 周，等 P0/P1 成立）

- 页面：今日 / 存档 / 搜索 / 画像 / 方向卡
- 推送：邮件 + 飞书（可选）
- 整合：code-platform 的 commit/issue 当作"进度"信号；小满做周五复盘的口吻层

**没通过 P0 就不做 P2**——内容不够好时，网站只是把噪音排版得更漂亮。

## 9. 评测怎么做（不追求论文级）

- 离线：30 条人工标"相关/不相关"，看 top-5 命中；nDCG@10 对比两个版本
- 忠实：抽 20 条摘要，检查每句能否在原文找到依据；引用覆盖率必须 100%
- 在线：打开率、保存率、行动率（这周是否执行了方向卡）
- 每周你自己写 3 行复盘（不是模型写），作为下一周的输入

## 10. 明确不做（至少前两周）

不做全量爬虫/绕过反爬；不做社区/评论；不做多用户；不做精美前端；不做语音；不接第二个角色模式（先把一个跑顺）。

## 11. 需要你定的四件事

1. **先服务哪个角色**：工程师（推荐，源好接、你自己就是用户）还是科研？
2. **进度从哪来**：每周手填三问（推荐，30 秒）/ GitHub 活动 / 笔记？
3. **日报送到哪**：邮件（推荐，零依赖）/ 飞书 / 只在网页看？
4. **语言**：中英混合（推荐）/ 中文优先？

## 12. 一个提醒

这个项目的成败不在"爬虫写得多好"，而在**第 8 天你还想打开它**。所以 P0 只做 5 条、只做 5 个源、只做 3 行摘要；先让自己愿意每天看，再谈网站和整合。
